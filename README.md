# Nothing to Watch — AV edition

A personal remake of the *There's nothing to watch...* film wall, running on my own
IMDb library instead of a public film database. Every title is a cell in a dense grid;
a fisheye lens follows the pointer, swelling whatever is under it into a readable poster
while the rest compresses into a mosaic.

2,100 titles · 21 genres · one self-contained HTML file · **dark only**.

## 1. Quick start

```bash
open "Nothing to Watch AV.html"
```

That is the whole thing. No build, no server, no dependencies. `index.html` redirects to
it, so serving the folder works too.

Rebuild after changing the CSVs:

```bash
cd pipeline && python3 pipeline.py
```

Plain Python 3, no packages to install.

## 2. How posters work

**Short version:** `fetch_tmdb.py` downloads a small poster for every title into
`pipeline/artwork/`, and the app loads them from there by relative path. Run it once,
rebuild, and the wall is full of real posters — including on GitHub Pages, since the
images are committed with the repo.

### The flow

```
IMDb const        fetch_tmdb.py                      pipeline.py            the app
tt0816692    →    TMDB /find  →  poster_path    →    sees the file      →  <img src=
                  (your key)     downloads w185      and sets a:1          "pipeline/artwork/
                                 to pipeline/                              tt0816692.jpg">
                                 artwork/tt0816692.jpg
```

The app stores no paths per title — only a flag saying the file existed at build time.
The filename is always `pipeline/artwork/<imdb-id>.jpg`, so the URL is derivable.

### Doing it

```bash
export TMDB_API_KEY=xxxxxxxxxxxx        # free: themoviedb.org/settings/api
cd pipeline
python3 fetch_tmdb.py                   # ~15 min for 2,100 titles, resumable
python3 pipeline.py                     # flags which titles got artwork
```

`fetch_tmdb.py` is incremental: it skips titles whose image is already on disk, so
adding films later only fetches the new ones. It writes each file to `.part` and renames,
so an interrupted run never leaves a half-written JPEG. Progress and each title's TMDB
overview are cached in `pipeline/tmdb_cache.json`.

### Why w185

Measured, not guessed — the wall's most magnified cell is about 160 px wide, so anything
larger is wasted pixels:

| Size | Per poster | × 2,100 |
|---|---|---|
| w92 | 10.0 KB | 20 MB — soft at full magnification |
| **w185** | **16.6 KB** | **33 MB — the choice** |
| w342 | 65.8 KB | 131 MB — 4× the weight for no visible gain |

w154 costs 16.0 KB, so w185 is 4% larger for a noticeably sharper magnified cell. 33 MB
commits and serves from GitHub Pages comfortably.

### Loading is bounded

Only cells wider than `TILE_MIN_W` (9 px) request artwork, at most `MAX_INFLIGHT` (16)
loads are in flight, and requests are issued **largest cell first**. That last part
matters: drawing runs smallest-first (so magnified cells overlap seams), and asking for
images inside the draw loop spent the entire budget on the tiny periphery — the magnified
cells under the pointer, the only place a poster is legible, never loaded at all.

### Without the artwork

The app still works. Every cell falls back to a neutral card whose luminance is derived
from its IMDb id, with the title and year typeset once it is big enough.

## 3. Design

Matched to the original rather than to my other projects:

- **Dark only.** No light mode, no theme toggle, no theme key in storage.
- **Palette** is the original's: `#0a0a0a` background, `#fafafa` foreground, zinc greys,
  `#262626` borders. **No colour anywhere** — no genre hues, no gold stars.
- **DM Sans**, the original's typeface.
- **No top bar.** Ghost icon buttons float at the top right on 36 px padding, the way the
  original's navbar sits; the canvas runs edge to edge behind them.
- **The selected film is an overlay, not a side panel** — tagline, oversized title with a
  lighter year beside it, white genre pills, and a circular percentage gauge, over a soft
  radial scrim. Because it floats rather than displacing the wall, the wall never has to
  move to make room (an earlier side-panel version had to squeeze the whole grid sideways).
- **Typographic intro** — `"There's nothing to watch…"` in black italic with an animated
  ellipsis, plus an About panel carrying the credits.

One difference is unavoidable: the original draws on ~10,000 films, so its cells are much
smaller and its compressed field much finer. With 2,100 titles the cells are roughly twice
the size at the same viewport. `LENS_D` is tuned to compensate, but the field cannot be as
dense as a library five times larger.

## 4. What is deliberately *not* here

The original renders tens of thousands of posters and has to negotiate with the hardware
to do it. My library is 2,100 titles, so none of that machinery is warranted:

| The original has | Here |
|---|---|
| WebGL 2.0 + Voroforce engine, GLSL shaders, worker threads | one 2D canvas, no dependencies |
| Device-class detection, quality presets, cell-limit selector | none — see below |
| Low-FPS alerts, performance monitor, telemetry | none |
| React 19, Vite, Bun, Tailwind, Radix, Zustand, Playwright, Vitest | none |
| Multi-resolution media atlases, chunked loaders | one image size (w185), loaded lazily |
| `.env` files, security headers, sitemap, SEO, analytics | none |

**There are no performance or quality settings in the UI, by design.** Measured on this
library, geometry and sorting cost **0.41 ms per frame** — about 2.5% of a 60 fps
budget. There is nothing to tune.

## 5. The lens

A grid of 2:3 cells covers the viewport. Every point of the grid's *lattice* is displaced
away from the pointer by a gain that falls off with distance:

```
wp = pt + d · k(t),      k(t) = (D+1) / (D·t + 1)
```

`t` is the distance normalised so `t = 1` lands on the viewport edge, using a **superellipse
norm** — `t = (nx⁴ + ny⁴)^¼`, with `nx`,`ny` scaled by the distance to the edge on each axis.
Three things fall out of that:

- **`k(1) = 1`, so the wall's edge is a fixed point** — nothing is pushed off screen no
  matter how strong the lens. An earlier version normalised by the farthest corner, and at
  high `D` that flung most of the wall out of frame, leaving only a few huge cells visible.
- **The superellipse is smooth**, unlike `min(distance-to-each-edge)`, whose kink along the
  diagonals produced a bowtie-shaped magnified region with streaks at the corners.
- **Cell size follows for free**: tangential stretch is `k`, radial stretch is
  `(D+1)/(D·t+1)²`. At the edge that is ~1 across and ~1/20 deep, so periphery cells become
  the fine speckled slivers the original shows.

`LENS_D` (default 20) is the whole feel: how tight the readable orb is against that field.

Two more details, each of which was a visible bug first:

- **The warp is applied to the lattice, not to cell centres.** Warping centres spreads them
  apart faster than it grows them, which tears a black cross open along the pointer's row
  and column. Sharing corners means no seam can open.
- **The opening focus sits at a cell centre, not the screen centre.** Dead centre is a
  lattice intersection, and a focus exactly on a lattice line is degenerate — that row maps
  along one line and renders as a bright streak.

The grid is laid out `OVERSCAN` (1.22×) larger than the viewport, because a superellipse's
corner sits ~19% past `t = 1` and is pulled slightly inward; the overscan keeps the corners
covered.

## 6. The menu

Deliberately the same set as my [AV Movie Universe](../AVMovieUniverse) galaxy map, so
both projects behave identically over the same library:

- **Search** — title or director; picking a result flies the lens to it and clears the
  query (leaving it set keeps the search filter live and hands you a near-black wall).
- **Watch tonight** — a random *unwatched* title respecting your filters.
  **Random film** / **Random series** do the same for one type.
- **All / Unwatched / Rated** — `Rated` means "has a score of mine".
- **My rating** — a 1–10 tick row.
- **All / Films / Series / Games**.
- **Genres** — toggle any of the 21; each row shows watched/total and a share bar.
- **Arrange: Genre · Rating · Year · Shuffle** — the wall is a plain sequence, so sort
  order *is* the layout. Genre-major is the default and gives each genre a visible band.
- **Hide filtered out** — off by default (non-matching cells stay in place, dimmed, so
  the wall keeps its shape); on, they are dropped and the grid re-packs.

**Keyboard** — `←↑↓→` move · `/` search · `w` watch tonight · `m` menu · `Esc` close.

The arrow keys are how you scroll: there is no camera to pan, so moving the focus one cell
at a time *is* the scroll. A held key glides the lens across the wall, and whatever it lands
on opens in the overlay. The pointer takes control back on any real mouse movement.

## 8. Data

The data half of `pipeline.py` is deliberately identical to
[AV Movie Universe](../AVMovieUniverse)'s, so both projects classify a title the same way:

- Both CSVs are de-duplicated by IMDb const; a title in both counts as watched.
- IMDb tags up to four genres; `GENRE_PRIORITY` picks the most specific. Genres with
  fewer than 8 titles fold into the next best, so there is no one-cell genre.
- **Series length is an approximation.** IMDb's runtime is *per episode*, so
  `EPISODES = {'TV Series': 20, 'TV Mini Series': 6}` scales it to a rough total. The
  export has no episode count; the panel is honest about it (`30m/ep · ≈10h total`).
- 76 titles have no runtime and are filled from library medians, marked `(est.)`.
- ~465 have no director credit — normal, since IMDb credits series to creators.

**Watched status and ratings are read-only**, seeded into `localStorage` once (guarded by
`SEED_VERSION`). To change them, re-export from IMDb and rebuild.

### Refreshing from newer IMDb exports

Save the new exports over the two CSVs keeping the filenames, re-run `fetch_tmdb.py`
(only new titles are looked up), re-run `pipeline.py`, and bump `SEED_VERSION` — ids are
assigned by sort order, so a changed library shifts them.

### Data model, and one trap

```js
{ id, t, d, g, ty, tt, yr, rt, m, ep, ir, nv, c, ot?, e?, p?, b? }
//  t=title  d=director(s)  g=genre  ty=Movie|Series|Game  tt=exact IMDb type
//  yr=year  rt=runtime per episode/film  m=total watch minutes  ep=episode multiplier
//  ir=IMDb score  nv=vote count  c=IMDb const  ot=original title  e=runtime estimated
//  p=TMDB poster path  b=TMDB backdrop path
```

> The year field is `yr`, not `y`. In the sibling galaxy-map project the layout writes
> `b.x` / `b.y` onto these objects as coordinates, and a field called `y` gets silently
> overwritten. The name is kept here so the two data models stay interchangeable.

## 9. Knobs

All in the template string inside `pipeline/pipeline.py`.

| What | Find | Now | Effect |
|---|---|---|---|
| Lens strength | `var LENS_D=20;` | 20 | The whole feel. Higher = more extreme magnification. |
| Lens smoothing | `POINTER_EASE=0.16` | 0.16 | How fast the lens catches the pointer. Lower = more glide. |
| Cell shape | `CELL_ASPECT=2/3` | 2/3 | Poster proportions; also sets the column count. |
| Quad/card cutoff | `QUAD_MAX=13` | 13 | Below this width a cell is a raw lattice quad. |
| Card inset | `CELL_GAP=0.9` | 0.9 | Spacing between magnified posters. |
| Artwork threshold | `TILE_MIN_W=9` | 9 | Minimum cell width that requests a poster. |
| Concurrent loads | `MAX_INFLIGHT=16` | 16 | In-flight artwork requests. |
| Poster size | `IMG_SIZE` in fetch_tmdb.py | w185 | Re-run the fetcher after changing it. |
| Grid overscan | `OVERSCAN=1.22` | 1.22 | How far the grid extends past the viewport. |
| Fallback tone | `var a=Math.round(32+t*28)` | 32–60 | Brightness range of poster-less cards. |
| Default sort | `state.sort:"genre"` | genre | Opening arrangement. |
| Series scaling | `EPISODES` (Python) | 20 / 6 | Per-episode → total runtime. |
| localStorage | `ntwav-watched-v1`, `ntwav-ratings-v1`, `ntwav-seed-v1` | — | Bump a version to reset. |
